# Agro+ performance baseline — 2026-11-08

## Environment

- Device: Android model `21061119AG`, Android 13/API 33, 1080 × 2400; display supports 60/90 Hz and was reporting mode 60 Hz during capture.
- Build: Flutter 3.47.7 stable, Dart 3.13.5, Android **Profile** mode; Impeller/OpenGLES.
- Installed target-specific Profile APK: 47,185,566 bytes (~45.0 MiB). A separate universal `flutter build apk --profile` output was 84.5 MB; do not compare those artifacts as if they were the same ABI package.

## Startup observations

- `flutter run --profile --trace-startup` recorded `timeToFirstFrameMicros: 712,688` (~0.71 s), `timeToFirstFrameRasterizedMicros: 2,749,623` (~2.75 s), and `timeToFrameworkInitMicros: 679,267` (~0.68 s).
- Android logcat reported 174–177 skipped frames during the first Profile launch and one slow bitmap upload. This was a cold build/install launch; repeat after warming the installed build before attributing it to production UI work.
- Profile bootstrap logged `Agro+ servicios y perfil: 2999 ms`. This matches the deliberately retained three-second brand minimum and is not evidence that Supabase initialization alone takes three seconds.
- A graphics-info snapshot after startup contained only two frames, both startup frames; its 100% janky percentage is too small a sample to use as an interaction baseline.
- `dumpsys meminfo` at the home screen showed `TOTAL PSS: 169,659 KB` (~165.7 MiB), `TOTAL RSS: 263,886 KB` (~257.7 MiB). One sample only; establish a stable post-warm baseline after module flows are exercised.

- Relevant indexes exist for published products, producer ID, photos by product, messages by chat, and chats by buyer/product.
- Supabase performance advisor reports 14 unused indexes. With only 8 products and no chat rows, this is not a basis to drop indexes; leave them in place and revisit with production query volume.
- The map and chat flows have not yet been physically exercised in this capture. `adb shell input tap` is blocked on this Redmi by Android's `INJECT_EVENTS` permission, so do not treat an automated shell tap as a valid interaction result.

## Initial decision

- Keep the branded splash, but use the measured 800 ms minimum and let service/profile readiness determine longer cold starts.
- Defer catalog/chat pagination, map query narrowing, and schema/index changes until a larger dataset or a Profile measurement demonstrates a real benefit. Current row counts are too small for those changes to improve the tested experience and they add state/Realtime complexity.
- Continue with shared motion/rebuild cleanup because that matches the user's explicit request; use widget/profile evidence to choose only repeatable effects or rebuilds to change.
- Repeat startup once after the Profile build is warmed. Record the module-specific frame/network/memory baseline when a real interaction path is available; do not label the 2-frame startup snapshot as representative.

## Latest performance review - 2026-11-08

- The minimum branded startup hold was reduced from 3 seconds to 800 ms in `lib/main.dart`; authentication and profile resolution still complete before the app routes into the signed-in experience.
- Three Profile launches before this change measured bootstrap at about 3,000 ms because of the fixed hold. After the change, one cold run measured 2,629 ms of bootstrap; two warm runs measured 800 ms. Android `am start -W` reported 3,638 ms cold, then 1,595 ms and 1,281 ms warm. Those values include device/engine startup and are specific to this older Redmi.
- A temporary phase trace showed cold `Supabase.initialize` at 1,770 ms and warm initialization at 136-183 ms; auth/profile resolution was 269-457 ms. The phase trace was removed after measurement.
- Profile memory on the map was about 202,217 KB PSS (~197 MiB). Two physical pans and one bottom-sheet expansion produced no new Choreographer skipped-frame messages in the captured log, but `dumpsys gfxinfo` retained only three frames. This is not enough data to claim smooth frame pacing or a measured FPS improvement.
- Cold/warm startup still logged skipped frames (63/169 cold, 67/54 on one warm sample, and 43 on another). Startup jank remains to be profiled separately; do not attribute it solely to the age of the phone.
- The full Flutter suite passed: 153 tests. `flutter analyze --no-pub`, `git diff --check`, and `flutter build apk --debug` also completed successfully after the final fixes. This is static/widget/build verification, not a replacement for trying catalog, chat, and map flows on multiple devices.
- `.env` and `.env.local` remain ignored; `.env.example` contains placeholders only. Supabase migrations are included as source files, but pushing them to GitHub does not apply them to the connected database.
